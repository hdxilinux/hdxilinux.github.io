Meet hdx

hdx is the package manager of HDXI. It is written entirely in shell and works the way a BSD ports system does: instead of downloading prebuilt packages, it builds software from source on your own machine.

Every program in HDXI beyond the base tarball is a port. hdx finds the port, fetches and checks the source, builds it and installs it. Because the whole tool is a handful of readable scripts, you can open it and see exactly what it does.

Ports, not binaries

A port is a small folder with a make.sh recipe. It downloads the upstream source, builds it and installs it to /usr/local.

Pinned and verified

Each recipe pins the SHA256 of its source, and the download is checked against it before anything is built.

Dependencies

A port lists what it needs, one port per line, in a deps file.

Four port classes

base is the system itself, util holds small tools, devel has libraries and build tools, and misc is everything else. The class is the first part of a port’s name, as in util-wpa_supplicant.

Protected base

Ports in the base class are protected from removal, so you can’t uninstall the init or the kernel by accident.

Asks before it removes

Removing a port shows the binaries hdx found and any uninstall script, then asks first. If a build fails, hdx marks nothing as installed and keeps the source so you can fix it and try again.

A plain git tree

The ports tree lives at /hdxp as an ordinary git clone, so updating it is a git pull.
